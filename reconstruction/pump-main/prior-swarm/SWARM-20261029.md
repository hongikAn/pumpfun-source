# Main Pump parallel reconstruction swarm

## Objective and acceptance

Main Pump only. Recover compiler-produced Rust source for every remaining function and ultimately establish raw byte identity, not merely normalized-window identity. Never inject original machine code, patch emitted bytes, add padding, alter the scorer, or treat diagnostic similarity as acceptance.

A target is normalized-complete only when the official local scorer reports that original window as `normalized: true`. It is raw-complete only when `raw: true`. Any candidate must retain every baseline normalized/raw membership unless a separately verified tradeoff produces a net improvement and is explicitly marked. Whole-ELF completion is not established by function-window counts alone.

## Isolation and tools

Each agent owns exactly one `lanes/<lane>/` tree. Do not edit maintained `programs/`, another lane, shared baseline binaries/sources, or root-level prior untracked files. Copy a prior source tree into your lane before changing it. All generated evidence stays inside this swarm directory.

The external harness and its required binary/toolchain inputs were copied locally. Use `tools/harness`, not the external original harness. The compiler itself remains the project-pinned installed SDK/toolchain input.

Build an isolated source tree:

```sh
python3 research/goal-pump-main-swarm-20261029/tools/harness/fastbuild.py \
  --src research/goal-pump-main-swarm-20261029/lanes/<lane>/source \
  --work research/goal-pump-main-swarm-20261029/lanes/<lane>/build \
  --out research/goal-pump-main-swarm-20261029/lanes/<lane>/outputs/<trial> \
  --recipe identity
```

Score without changing the acceptance rule:

```sh
python3 research/goal-pump-main-swarm-20261029/tools/harness/score.py \
  research/goal-pump-main-swarm-20261029/lanes/<lane>/outputs/<trial>/unstripped.so \
  --baseline research/goal-pump-main-swarm-20261029/baseline/score.json \
  --json research/goal-pump-main-swarm-20261029/lanes/<lane>/outputs/<trial>/score.json \
  --quiet
```

Inspect candidates and original assembly with `tools/harness/win.py`. Builds share six local slots through `tools/locks`; do not raise concurrency or run duplicate builds.

## Mandatory attempt ledger and non-repetition

Before a trial, read the named prior-art records and search existing attempt logs for the same mechanism. Give every trial a stable, descriptive dedupe key including target, source/base, and mechanism. Check it before execution:

```sh
python3 research/goal-pump-main-swarm-20261029/log_attempt.py check --dedupe-key <key>
```

Immediately log every analysis trial, build, compile failure, rejected candidate, and success:

```sh
python3 research/goal-pump-main-swarm-20261029/log_attempt.py record \
  --lane <lane> --approach <approach> --target <0x...> \
  --dedupe-key <key> --hypothesis <concise mechanism> \
  --status <analyzed|built|compile-failed|rejected|partial|normalized-match|raw-match> \
  --data '{"output":"lanes/<lane>/outputs/<trial>","normalized":1019,"raw":188,"gains":[],"losses":[],"notes":"..."}'
```

The logger uses a locked shared JSONL file. A duplicate key is rejected. Include actual hashes and source diffs in `data` or the referenced output. Do not rename an already tried mechanism to evade deduplication. Equivalent-output results are important negative evidence and must be logged too.

Each lane ends with `lanes/<lane>/SUMMARY.json` containing targets, attempts, best candidate, strict gains/losses, rejected mechanisms, unresolved residuals, and the next genuinely novel experiment. Return only a compact conclusion to the coordinator; keep bulk evidence in files.

## Required evidence distinctions

Distinguish direct observation (bytes, disassembly, compiler IR, runtime record), inference (source boundary or guard origin), and unknowns. Static matching does not prove runtime behavior. Runtime similarity does not prove bytes. Preserve compile failures and negative trials. No network or live-chain execution is needed or authorized by this task.
